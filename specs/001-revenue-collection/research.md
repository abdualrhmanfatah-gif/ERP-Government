# البحث والقرارات: نظام إدارة وتوريد الإيرادات الحكومية

## قرارات البحث

### 1. استراتيجية التعديل المتزامن (Concurrency Control)

**المشكلة**: ماذا يحدث عند تعديل مستخدمين لنفس السند في نفس الوقت؟

**القرار**: RowVersion (Optimistic Concurrency)

**المبرر**:
- الكيانات الموجودة تستخدم بالفعل `byte[] RowVersion`
- EF Core يدعم Optimistic Concurrency تلقائيًا
- لا حاجة لقفلUNC (Locking) — الأداء أفضل لنظام < 500 مطالبة/شهر
- عند التعديل المتزامن، يُرجع 409 Conflict

**البدائل المرفوضة**:
-悲观锁 (Pessimistic Locking): يُبطئ الأداء ولا يلزم لهذا الحجم

---

### 2. التكامل البنكي (Bank Integration)

**المشكلة**: كيف يتم التحقق من تصفية/ارتجاع الشيكات من البنك؟

**القرار**: يدوي — المستخدم يُدخل البيانات يدويًا

**المبرر**:
- البنوك اليمنية قد لا توفر API للمقارنة
- التكلفة أقل بكثير
- حجم البيانات < 500 مطالبة/شهر — التسجيل اليدوي ممكن

**البدائل المرفوضة**:
- API تلقائي: تكلفة عالية، البنوك قد لا تدعم

---

### 3. عدد الشيكات لكل سند قبض

**المشكلة**: هل يمكن أن يحتوي سند قبض على عدة شيكات؟

**القرار**: شيك واحد فقط لكل سند قبض

**المبرر**:
- FR-04 في المواصفة: "شيك واحد لكل سند قبض — لا يُسمح بعدة شيكات في سند واحد"
- يُبسّط منطق الحسابات (AvailableAmount)
- يُبسّط القيود المحاسبية

**البدائل المرفوضة**:
- عدة شيكات: تعقيد في الحسابات والقيود

---

### 4. حجم البيانات المتوقع

**المشكلة**: كم عدد المطالبات المتوقع شهريًا؟

**القرار**: أقل من 500 مطالبة شهريًا

**المبرر**:
- إجابة المستخدم مباشرة
- نظام حكومي متوسط الحجم
- لا حاجة لأداء خاص (caching, sharding)

**المتطلبات الفنية**:
- لا حاجة لـ Pagination في الاستعلامات (< 500 سجل)
- لا حاجة لـ Indexing خاص
- EF Core Async كافي

---

### 5. الصلاحيات والأدوار

**المشكلة**: هل يوجد تمييز بين المستخدمين في الصلاحيات؟

**القرار**: مستخدم واحد فقط — لا تمييز أدوار

**المبرر**:
- إجابة المستخدم مباشرة
- قد يكون نظام لمستخدم واحد (أمين الصندوق)

**الملاحظة**: الكود الحالي يحتوي PermissionCodes — يمكن تجاهلها في هذا النطاق

## أفضل الممارسات المطبقة

| الممارسة | التطبيق |
|----------|---------|
| Domain Events | MediatR INotification مع IHasSourceEntity |
| CQRS | Command/Query مفصولة في ملفات منفصلة |
| Optimistic Concurrency | byte[] RowVersion في جميع الكيانات |
| Document Numbering | IDocumentSequenceService - {PREFIX}-{D6} |
| Audit Trail | BaseAuditableEntity + DocumentStatusLog |
| Validation | FluentValidation مع IApplicationDbContext |
| Result Pattern | Result<T> لكل command |
| Minimal APIs | IEndpointGroup مع auto-registration |

## المخاطر والتحذيرات

| المخاطة | التأثير | التخفيف |
|---------|---------|---------|
| تعديل متزامن | فقدان بيانات | RowVersion + 409 Conflict |
| تحصيل زائد | عدم توافق محاسبي | AvailableAmount check |
| قيود محاسبية خاطئة | عدم توافق دفتر الأستاذ | RevenueJournalEntryService |
| فقدان سجل رقابي | عدم امتثال قانوني | DocumentStatusLog |
