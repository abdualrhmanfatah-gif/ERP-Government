# مواصفة نظام إدارة وتوريد الإيرادات الحكومية (التحصيل الفعلي)

## النظرة العامة

نظام إدارة وإصدار مطالبات الإيرادات الحكومية وأوامر التحصيل وسندات القبض (نقدي/شيكات) والحوافظ المصرفية وتصفية/ارتجاع الشيكات. يعتمد النظام مبدأ **الاعتراف بالإيراد عند التحصيل الفعلي**، بحيث تُسجل القيود المحاسبية حصريًا عند تحصيل النقد أو تصفية الشيك، بينما تبقى المطالبات وأوامر التحصيل سجلات رقابية إدارية.

**القانون المالي المرجعي**: القانون المالي رقم (8) لسنة 1990م ولائحته التنفيذية.

---

## سيناريوهات المستخدم

### السيناريو 1: إصدار مطالبة إيرادية وتحصيلها نقديًا
1. يُدخل الموظف المطالبة الإيرادية (رقم المطالبة، التاريخ، الجهة، المبلغ)
2. تمر المطالبة بسير الاعتماد: Draft → PendingApproval → Open
3. يُصدر أمر تحصيل (order number، المبلغ المفوض)
4. يُصدر سند قبض نقدي (voucher) ويعتمد
5. **عند الاعتماد**: ينشأ القيد المحاسبي (مدين: نقدية لدى أمين الصندوق، دائن: حساب الإيراد)
6. تُحدَّث حالة المطالبة ديناميكيًا: Open → PartiallySettled → Settled

### السيناريو 2: تحصيل بالشيكات وإيداعها
1. يُصدر سند قبض بالشيك ويعتمد
2. **عند الاعتماد**: ينشأ القيد الوسيط (مدين: شيكات برسم الإيداع، دائن: متحصلات شيكات معلقة) — لا يُعترف بالإيراد بعد
3. تُرسل الشيكات عبر حافظة إرسال شيكات (48) إلى البنك
4. **عند اعتماد الحافظة**: يُحوَّل القيد (مدين: شيكات تحت التحصيل، دائن: شيكات برسم الإيداع)
5. عند تصفية الشيك في البنك:
   - **قيد 1**: مدين حساب البنك / دائن شيكات تحت التحصيل
   - **قيد 2**: مدين متحصلات شيكات معلقة / دائن حساب الإيراد
6. تُحدَّث حالة المطالبة ديناميكيًا

### السيناريو 3: ارتجاع شيك
1. يُكتشف ارتجاع شيك من البنك
2. **عند الاعتماد**: يُعكس القيد الوسيط (مدين: متحصلات شيكات معلقة، دائن: شيكات تحت التحصيل)
3. لا يُعكس إيراد لأنه لم يُعترف به بعد
4. يُفك الحجز على المبلغ ويعود متاحًا للمطالبة

### السيناريو 4: تحصيل نقدي وتوريد للبنك
1. يُحصّل المبلغ نقدًا عبر سند قبض نقدي
2. يُودَّع النقد في البنك عبر حافظة توريد نقدي (47)
3. **قيد الحافظة**: مدين حساب البنك / دائن نقدية لدى أمين الصندوق (نقل أمانة فقط)

### السيناريو 5:رقابة التحصيل الزائد
1. يتحقق النظام من المبلغ المتاح قبل اعتماد أي سند قبض
2. المبلغ المتاح = مبلغ المطالبة − (المحصّل + شيكات معلقة)
3. يُمنع إصدار سند قبض يتجاوز المبلغ المتاح

## المتطلبات الوظيفية

### FR-01: إدارة المطالبات الإيرادية
- إنشاء مطالبة إيرادية برقم تسلسلي تلقائي
- تتبع الحالات: Draft → PendingApproval → Open → PartiallySettled → Settled → WrittenOff
- حساب المبالغ ديناميكيًا من الحركات المحاسبية (لا قيم مخزنة)
- ربط المطالبة بالجهة (Party) والمبالغ
- **الصلاحيات**: مستخدم واحد فقط — لا تمييز أدوار

### FR-02: إدارة أوامر التحصيل
- إصدار أمر تحصيل لكل مطالبة
- التحقق من عدم تجاوز المبلغ المفوض للمطالبة
- تتبع الحالات: Draft → PendingApproval → Approved → PartiallyCollected → Collected → Cancelled
- لا قيد محاسبي عند الاعتماد (تفويض فقط)

### FR-03: سندات القبض النقدية
- إصدار سند قبض نقدي وربطه بأمر التحصيل
- عند الاعتماد: قيد محاسبي تلقائي (نقدية صندوق → إيراد)
- تحديث حالة المطالبة ديناميكيًا

### FR-04: سندات القبض بالشيكات
- إصدار سند قبض بالشيك وتسجيل بيانات الشيك (رقم، بنك، تاريخ، مبلغ)
- **شيك واحد لكل سند قبض** — لا يُسمح بعدة شيكات في سند واحد
- عند الاعتماد: قيد وسيط (شيكات برسم الإيداع → متحصلات معلقة)
- لا يُعترف بالإيراد عند هذا العنوان

### FR-05: حافظة توريد نقدي (47)
- إنشاء حافظة توريد نقدي وتجميع سندات القبض النقدية
- عند الاعتماد: قيد نقل أمانة (بنك → نقدية صندوق)
- لا يُعاد إثبات الإيراد

### FR-06: حافظة إرسال شيكات (48)
- إنشاء حافظة إرسال شيكات وتجميع شيكات برسم الإيداع
- عند الاعتماد: قيد تحويل (شيكات تحت التحصيل → شيكات برسم الإيداع)
- تحديث حالة الشيكات: UnderCollection

### FR-07: تصفية الشيكات
- تسجيل تصفية شيك من البنك **يدويًا** (المستخدم يُدخل بيانات التصفية)
- قيد مزدوج: (1) إثبات رصيد البنك، (2) الاعتراف بالإيراد
- تحديث حالة الشيك: Cleared
- تحديث حالة المطالبة ديناميكيًا

### FR-08: ارتجاع الشيكات
- تسجيل ارتجاع شيك **يدويًا** (المستخدم يُدخل بيانات الارتجاع)
- قيد عكس القيد الوسيط (متحصلات معلقة → شيكات تحت التحصيل)
- لا يُعكس إيراد (لم يُعترف به)
- يُفك الحجز على المبلغ

### FR-09: رقابة التحصيل الزائد
- حساب ديناميكي: AvailableAmount = ClaimAmount − CollectedAmount − UnderCollectionAmount
- منع إصدار/اعتماد سند قبض يتجاوز AvailableAmount
- رسالة خطأ واضحة للمستخدم

### FR-10: التقارير والإحصائيات
- عرض حالة المطالبات (Open/PartiallySettled/Settled)
- عرض شيكات تحت التحصيل والمبالغ المحتجزة
- إجمالي المحصّل لكل مطالبة

## معايير النجاح

| المعيار | القيمة |
|---------|--------|
| إصدار مطالبة + أمر تحصيل + سند قبض نقدي | ≤ 3 دقائق |
| حساب المبلغ المتاح | فوري (من الحركات المحاسبية) |
| منع التحصيل الزائد | 100% — لا يُسمح بأي سند قبض يتجاوز المتاح |
| القيود المحاسبية | تلقائية وعند الاعتماد فقط (لا قيود يدوية) |
| تتبع الشيكات | من receipt إلى clearance/bounce مع قيود محاسبية |
| سجل رقابي | كل حركة لها سجل رقابي كامل |

## القيود والمسلمات

- **القانون المرجعي**: القانون المالي رقم (8) لسنة 1990م ولائحته التنفيذية
- **مبدأ الاعتراف بالإيراد**: عند التحصيل الفعلي فقط (نقدي أو تصفية شيك)
- **المطالبات وأوامر التحصيل**: سجلات رقابية إدارية فقط (لا قيود محاسبية)
- **القيود المحاسبية**: تتولد تلقائيًا عند اعتماد السندات والحوافظ
- **حسابات الأستاذ العام**: نقدية لدى أمين الصندوق، شيكات برسم الإيداع، متحصلات شيكات معلقة، شيكات تحت التحصيل، حساب البنك، حساب الإيراد
- **العملة**: ريال يمني
- **عدم السماح بالتحصيل الزائد**: قاعدة جامدة لا يمكن تجاوزها
- **التعديل المتزامن**: قفل على مستوى السجل (Record-level locking) — يُمنع التعديل المتزامن لنفس المستند
- **الصلاحيات**: مستخدم واحد فقط — لا تمييز أدوار أو صلاحيات
- **التكامل البنكي**: يدوي — المستخدم يُدخل بيانات تصفية/ارتجاع الشيكات يدويًا
- **عدد الشيكات**: شيك واحد فقط لكل سند قبض
- **حجم البيانات المتوقع**: أقل من 500 مطالبة شهريًا
