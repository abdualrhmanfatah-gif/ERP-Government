# LIFECYCLE-047: دورة حياة المساعدة المرضية وتسلسل العمليات

## نظرة عامة

هذه الوثيقة تصف دورة حياة عملية المساعدة المرضية من الإنشاء إلى الإغلاق، مع تسلسل العمليات وحالة كل كيان في كل مرحلة.

---

## الأطراف (Actors)

| الرمز | الدور | الصلاحيات |
|---|---|---|
| **مُدخل** | موظف إدخال | إنشاء طلب + إعداد أمر الصرف |
| **مُراجع** | مسؤول مالي أول | اعتماد أول (توقيع واحد) |
| **مُعتمد** | مسؤول مالي ثاني | اعتماد ثاني (توقيع ثاني) |
| **محاسب** | محاسب رئيسي | ترحيل القيود اليومية |
| **خزينة** | مسؤول الخزينة | تسجيل الدفع الفعلي |

---

## الكيانات المشاركة

```
┌─────────────────────────┐
│   طلب صرف (DisbursementRequest)   │
│   الحالة: Draft → Approved → Disbursed │
└──────────────┬──────────┘
               │ 1:1
               ▼
┌─────────────────────────┐
│   أمر صرف (PaymentOrder)          │
│   الحالة: Draft → Submitted → ... → Paid │
└──────────────┬──────────┘
               │ N:1
               ▼
┌─────────────────────────┐
│   قيد يومية (JournalEntry)        │
│   الاستحقاق: Draft → Posted       │
│   السداد: Draft → Posted          │
└─────────────────────────┘
```

## دورة الحياة الكاملة

### المرحلة 0: إنشاء طلب المساعدة

```
العملية: إنشاء طلب صرف جديد
المدخل: مُدخل
الأمر: CreateDisbursementRequestCommand
```

| الكيان | الحالة قبل | الحالة بعد |
|---|---|---|
| DisbursementRequest | — | **Draft** |

**البيانات المدخلة**:
- اسم المستفيد
- المبلغ المطلوب
- العملة
- الغرض (مساعدة مرضية)
- السنة المالية

**المخرجات**:
- رقم طلب صرف (مُولّد تلقائياً `DR-NNNNNN`)
- الملفات المرفقة (التقرير الطبي، المستندات)

```
┌──────────────────────────────────────────────┐
│  1. إنشاء طلب مساعدة                        │
│  ─────────────────────                       │
│  مُدخل → يملأ البيانات + يرفق المستندات      │
│  الحالة: ──────────────────→ Draft           │
│  رقم طلب: DR-000001                          │
└──────────────────────────────────────────────┘
```

### المرحلة 2: الاعتماد الأول (توقيع أول)

```
العملية: مراجعة واعتماد أول
المدخل: مُراجع
الأمر: ApproveDisbursementRequestCommand (step=1)
```

| الكيان | الحالة قبل | الحالة بعد |
|---|---|---|
| DisbursementRequest | PendingApproval | **PendingApproval** (لا يتغير) |
| ApprovalHistory | — | سجل: step=1, Action=Approve |

**التحقق**:
- الحالة = PendingApproval
- لا يوجد اعتماد سابق بنفس المبلغ

**النتيجة**:
- يُسجّل في `ApprovalHistory` بـ `ApprovalStep=1`
- الحالة تبقى `PendingApproval` (ينتظر التوقيع الثاني)

```
┌──────────────────────────────────────────────┐
│  3. الاعتماد الأول                           │
│  ─────────────────────                       │
│  مُراجع → يُراجع الطلب ويُصادق              │
│  الحالة: PendingApproval (تبقى كما هي)       │
│  ApprovalHistory: +1 سجل (step=1)            │
└──────────────────────────────────────────────┘
```

---

### المرحلة 3: الاعتماد الثاني (توقيع ثاني) — نقطة حرجة

```
العملية: الاعتماد النهائي + إنشاء أمر الصرف
المدخل: مُعتمد
الأمر: ApproveDisbursementRequestCommand (step=2)
```

| الكيان | الحالة قبل | الحالة بعد |
|---|---|---|
| DisbursementRequest | PendingApproval | **Approved** |
| PaymentOrder | — | **Draft** (جديد) |
| ApprovalHistory | 1 سجل | 2 سجلات |

**التحقق**:
- الحالة = PendingApproval
- المُعتمد ≠ المُراجع الأول (توقيعان مختلفان)
- المبلغ المُعتمد = المبلغ في الاعتماد الأول

**العمليات الذرية**:
1. تسجيل الاعتماد الثاني في `ApprovalHistory`
2. تغيير حالة `DisbursementRequest` إلى `Approved`
3. إنشاء `PaymentOrder` جديد:
   - `PaymentOrderNumber`: مُولّد تلقائياً `PO-NNNNNN`
   - `AmountGross`: المبلغ المُعتمد
   - `BeneficiaryName`: من طلب الصرف
   - `DisbursementRequestId`: ربط
   - `FundId = 0` (يُحدد لاحقاً عند الإعداد)
   - `Status = Draft`

**لا يزال**: لا يوجد قيد يومية

```
┌──────────────────────────────────────────────┐
│  4. الاعتماد الثاني + إنشاء أمر صرف         │
│  ─────────────────────                       │
│  مُعتمد → يُعتمد ويُنشئ أمر صرف             │
│  الحالة: PendingApproval ──→ Approved         │
│  أمر الصرف: ──────────────→ Draft            │
│  ApprovalHistory: +1 سجل (step=2)            │
│  PaymentOrder: PO-000001                      │
└──────────────────────────────────────────────┘
```

### المرحلة 4: إنشاء قيد الاستحقاق (اختياري — لكن مطلوب قبل الإعداد)

```
العملية: إنشاء قيد الاستحقاق المحاسبي
المدخل: محاسب
الأمر: CreateAccrualEntryCommand
```

| الكيان | الحالة قبل | الحالة بعد |
|---|---|---|
| DisbursementRequest | Approved | Approved |
| DisbursementRequest.AccrualJournalEntryId | null | **JournalEntry.Id** |
| JournalEntry | — | **Draft** (جديد) |
| JournalEntryLine (2 سطر) | — | مدين مصروف / دائن مورد |

**البيانات المدخلة**:
- حساب المصروف (المستخدم يختاره من دليل الحسابات)
- حساب الخصم/المورد (المستخدم يختاره)
- المبلغ (= المبلغ المُعتمد أو أقل)
- العملة
- مركز التكلفة (اختياري)

**التحقق**:
- الحالة = Approved
- لا يوجد قيد استحقاق مسبقاً (`AccrualJournalEntryId is null`)
- الحسابان نشطين ومنشورين ومخالفَيْن
- المبلغ > 0 و ≤ المبلغ المطلوب
- الفترة المالية نشطة

**القيود المُنشأة**:

```
┌────────────────────────────────────────────────────────┐
│  قيد الاستحقاق — مثال: مساعدة مرضية 100,000 ريال     │
│  ─────────────────────────────────────────────         │
│  الحساب                    │ مدين        │ دائن       │
│  ──────────────────────────┼─────────────┼──────────── │
│  352216 مساعدات مرضية      │ 100,000     │            │
│  2511 موردون محليون        │             │ 100,000    │
│  ──────────────────────────┼─────────────┼──────────── │
│  المجموع                   │ 100,000     │ 100,000    │
│  ──────────────────────────┴─────────────┴──────────── │
│  الحالة: Draft                                         │
│  المرجع: طلب صرف #DR-000001                           │
└────────────────────────────────────────────────────────┘
```

```
┌──────────────────────────────────────────────┐
│  5. إنشاء قيد الاستحقاق                     │
│  ─────────────────────                       │
│  محاسب → يُنشئ القيد بحسابات يختارها        │
│  JournalEntry: Draft ( AUTO-2026-000001 )    │
│  Dr: 352216 مساعدات مرضية     100,000        │
│  Cr: 2511 موردون محليون       100,000        │
│  ربط: AccrualJournalEntryId → JE-001         │
└──────────────────────────────────────────────┘
```

### المرحلة 5: ترحيل قيد الاستحقاق

```
العملية: إتمام دورة حياة القيد (Submit → Approve → Post)
المدخل: محاسب
الأمر: SubmitJournalEntry → ApproveJournalEntry → PostJournalEntry
```

| الكيان | الحالة قبل | الحالة بعد |
|---|---|---|
| JournalEntry | Draft | **Posted** |

**الدورة الفرعية للقيد**:

```
Draft → Submitted → Approved → Posted
  │         │          │         │
  │         │          │         └─ يظهر في التقارير المالية
  │         │          └─ جاهز للترحيل
  │         └─ قيد للمراجعة
  └─ مسودة
```

**الأوامر**:

| # | الأمر | الحالة قبل | الحالة بعد |
|---|---|---|---|
| 5a | `SubmitJournalEntryCommand` | Draft | Submitted |
| 5b | `ApproveJournalEntryCommand` | Submitted | Approved |
| 5c | `PostJournalEntryCommand` | Approved | Posted |

**بعد الترحيل**:
- القيد يظهر في: ميزانية عمومية، دفتر أستاذ، قائمة دخل
- التوفر المالي يحتسب المبلغ المُنفق

```
┌──────────────────────────────────────────────┐
│  6. ترحيل قيد الاستحقاق                     │
│  ─────────────────────                       │
│  محاسب → Submit → Approve → Post             │
│  الحالة: Draft → Submitted → Approved → Posted│
│  الآن يظهر في التقارير المالية               │
└──────────────────────────────────────────────┘
```

### المرحلة 6: إعداد أمر الصرف

```
العملية: تحديد الموازنة والبنك والمُستفيد
المدخل: مُدخل
الأمر: UpdatePaymentOrderCommand + SubmitPaymentOrderCommand
```

| الكيان | الحالة قبل | الحالة بعد |
|---|---|---|
| PaymentOrder | Draft | **Submitted** |

**البيانات المُحدّثة**:
- `FundId`: الصندوق
- `BudgetItemAllocationId`: تخصيص الموازنة
- `BankAccountId`: حساب البنك
- `CostCenterId`: مركز التكلفة

**التحقق**:
- الحالة = Draft
- **يجب أن يوجد `AccrualJournalEntryId`** (-linked_disbursement_request)
- فحص التوفر المالي (إذا كان هناك `BudgetItemAllocationId`)

**المحاذير**:
```
⚠️  فشل: يجب ترحيل قيد الاستحقاق أولاً
    سجّل قيد الاستحقاق من صفحة تفاصيل طلب الصرف.
```

```
┌──────────────────────────────────────────────┐
│  7. إعداد أمر الصرف                         │
│  ─────────────────────                       │
│  مُدخل → يُحدد الموازنة والبنك              │
│  فحص: هل يوجد AccrualJournalEntryId؟ ✅      │
│  الحالة: Draft ──────────→ Submitted          │
│  فحص الموازنة: متاح ≥ المبلغ الصافي ✅       │
└──────────────────────────────────────────────┘
```

### المرحلة 9: تسجيل الدفع — نقطة الترحيل الثانية

```
العملية: تسجيل الدفع الفعلي + إنشاء قيد السداد
المدخل: خزينة
الأمر: RecordPaymentCommand
```

| الكيان | الحالة قبل | الحالة بعد |
|---|---|---|
| PaymentOrder | SentToTreasury/Approved | **Paid** |
| DisbursementRequest | Approved | **Disbursed** |
| Payment | — | **Completed** (جديد) |
| JournalEntry (سداد) | — | **Draft** (جديد) |

**التحقق**:
- الحالة = Approved أو SentToTreasury
- لا يوجد دفع مُسجّل مسبقاً (دفعة واحدة فقط)

**العمليات الذرية**:

1. **استخراج حساب الخصم** من قيد الاستحقاق:
   ```
   accrualEntry.Lines.Where(Credit > 0).First().AccountId
   → 2511 (موردون محليون)
   ```

2. **إنشاء قيد السداد**:
   ```
   ┌────────────────────────────────────────────────────────┐
   │  قيد السداد — مثال: 100,000 ريال                      │
   │  ─────────────────────────────────────────────         │
   │  الحساب                    │ مدين        │ دائن       │
   │  ──────────────────────────┼─────────────┼──────────── │
   │  2511 موردون محليون        │ 100,000     │            │
   │  1821 الحسابات الجارية     │             │ 100,000    │
   │  ──────────────────────────┼─────────────┼──────────── │
   │  المجموع                   │ 100,000     │ 100,000    │
   │  ──────────────────────────┴─────────────┴──────────── │
   │  الحالة: Draft                                         │
   │  المرجع: أمر صرف #PO-000001                           │
   └────────────────────────────────────────────────────────┘
   ```

3. **إنشاء سجل الدفع**:
   - `PaymentNumber`: مُولّد `PAY-NNNNNN`
   - `Amount`: المبلغ الصافي
   - `Status`: Completed
   - `PaymentMethod`: شيك/تحويل
   - `ReferenceNumber`: رقم التحويل/الشيك

4. **تحديث الحالات**:
   - `PaymentOrder.Status = Paid`
   - `DisbursementRequest.Status = Disbursed`
   - `PaymentOrder.JournalEntryId = قيد السداد`

```
┌──────────────────────────────────────────────┐
│  10. تسجيل الدفع                             │
│  ─────────────────────                       │
│  خزينة → يُسجّل الدفع                       │
│  استخراج حساب الخصم من الاستحقاق: 2511       │
│  ────────────────────────────────────────     │
│  قيد السداد:                                 │
│  Dr: 2511 موردون محليون      100,000         │
│  Cr: 1821 الحسابات الجارية   100,000         │
│  ────────────────────────────────────────     │
│  PaymentOrder: Approved ──→ Paid              │
│  DisbursementRequest: Approved ──→ Disbursed  │
│  Payment: ────────────→ Completed             │
└──────────────────────────────────────────────┘
```

## المسارات البديلة

### مسار الإلغاء (قبل الدفع)

```
DisbursementRequest: Approved → Cancelled
PaymentOrder: Draft → Cancelled (إذا كان Draft)
```

**الأمر**: `CancelDisbursementRequestCommand`

**التحقق**:
- لا يوجد أمر صرف مدفوع
- الحالة = Draft أو Submitted (أو Approved إذا لم يُرسل للخزينة)

### مسار الإبطال (بعد الدفع)

```
PaymentOrder: Paid → Voided
DisbursementRequest: Disbursed → Invalidated
```

**الأمر**: `VoidPaymentOrderCommand`

**التحقق**:
- لا يمكن الإبطال بعد الدفع (مهم: يتحقق من عدم وجود دفع)

### مسار رفض الطلب

```
DisbursementRequest: PendingApproval → Rejected
```

**الأمر**: `RejectDisbursementRequestCommand`

**التحقق**:
- الحالة = PendingApproval

### مسار عكس قيد الاستحقاق

```
JournalEntry (استحقاق): Posted → Reversed
DisbursementRequest: AccrualJournalEntryId → null
```

**الأمر**: `ReverseJournalEntryCommand`

**التحقق**:
- القيد في حالة Posted فقط
- لا يمكن عكس قيد السداد إذا كان الدفع مُكتملاً

## التحقق من الاتساق

### في كل مرحلة، يجب التحقق من:

| التحقق | متى | كيف |
|---|---|---|
| المبلغ ≥ 0 | الإنشاء + التعديل | FluentValidation |
| الحالة صحيحة | كل أمر | فحص `Status == ExpectedStatus` |
| لا يوجد دفع مزدوج | تسجيل الدفع | فحص `Payments.Where(Completed)` |
| قيد الاستحقاق موجود | إعداد أمر الصرف | فحص `AccrualJournalEntryId.HasValue` |
| الحسابات نشطة | إنشاء القيد | فحص `Account.IsActive && IsPostable` |
| الفترة المالية نشطة | إنشاء القيد | فحص `FiscalPeriod.IsActive` |
| الموازنة كافية | إعداد أمر الصرف | `BudgetAvailabilityService.GetAvailableForAppropriationAsync` |
| توقيعان مختلفان | الاعتماد | فحص `firstApproval.ApproverUserId != secondUserId` |
| المبلغ متساوٍ | الاعتماد | فحص `firstAmount == secondAmount` |

## التدقيق والمراجعة

### في كل مرحلة، يمكن:

| الإجراء | الشروط |
|---|---|
| تعديل طلب الصرف | الحالة = Draft |
| إلغاء طلب الصرف | الحالة = Draft أو Submitted |
| رفض طلب الصرف | الحالة = PendingApproval |
| تعديل أمر الصرف | الحالة = Draft |
| إبطال أمر الصرف | الحالة = Approved أو SentToTreasury (وليس Paid) |
| عكس قيد يومية | الحالة = Posted فقط |
| إلغاء قيد يومية | الحالة = Draft أو Submitted |
