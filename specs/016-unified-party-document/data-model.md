### ApprovalHistory (MODIFY)

**Module**: `src/Domain/Security/Entities/ApprovalHistory.cs`
**Table**: `ApprovalHistory` (existing)

**Added fields**:

| Field | Type | Nullable | Constraints | Notes |
|-------|------|----------|-------------|-------|
| ApprovalStep | int | No | Required, Default: 1 | Step number in the approval chain |
| Action | ApprovalAction (int enum) | No | Required | Authoritative action enum |

**Retained fields** (unchanged):

| Field | Type | Notes |
|-------|------|-------|
| DocumentType | string | e.g., "Budget", "PaymentOrder" |
| DocumentId | int | Polymorphic FK |
| ApproverUserId | int | FK → Users |
| RequiredRole | string | Now populated with real role (never string.Empty for new records) |
| Decision | string | **RETAINED** as legacy note; Action is authoritative |
| DecisionAt | DateTimeOffset | |
| Reason | string? | When backfilling, original Decision string preserved here if Reason was empty |
| EvaluationSnapshot | string? | JSON-serialized approval rule evaluation |
| RowVersion | byte[] | Concurrency token |

**New enum — ApprovalAction** (`src/Domain/Security/Enums/ApprovalAction.cs`):
```
Submit = 0
Approve = 1
Reject = 2
Return = 3
Cancel = 4
```

**Backfill rules** (data migration):
- `Decision = "Approved"` → `Action = Approve`
- `Decision = "{from} -> {to}"` where to = "Submitted" or "PendingApproval" → `Action = Submit`
- `Decision = "{from} -> {to}"` where to = "Approved" → `Action = Approve`
- `Decision = "{from} -> {to}"` where to = "Cancelled" → `Action = Cancel`
- All other `{from} -> {to}` patterns → `Action = Approve` (default)
- When `Reason` is null/empty and `Decision` is not null, preserve original `Decision` string in `Reason`

## Migration Strategy

**Single EF Core migration** containing:
1. Create `Parties` table
2. Create `DocumentStatusLogs` table
3. Create `DocumentAttachmentRequirements` table
4. Alter `ApprovalHistory` — add `ApprovalStep`, `Action` columns
5. Alter `Attachments` — add `DocumentType`, `IsRequired`, `AttachmentTypeCode` columns
6. Data migration: Supplier → Party (with dedup)
7. Data migration: ApprovalHistory backfill (Action enum)
8. Data migration: Attachment DocumentType backfill from EntityName
9. Add FK constraints for VendorPartyId, SupplierPartyId, PartyId on migrated entities
10. Drop Suppliers table
11. Remove Suppliers DbSet from IApplicationDbContext
12. Seed DocumentAttachmentRequirements for Budget + Appropriation
13. Seed DocumentSequence entries for PTY, RCV, DSL, DSB, PAY prefixes

**Ordering**: Steps 1-5 (schema), 6-8 (data), 9 (FKs), 10-11 (cleanup), 12-13 (seeds)
